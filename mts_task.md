# AI Model Selection Assistant

## 1. Контекст

Вы разрабатываете ассистента для клиентов MWS, который помогает выбрать подходящую GPT Model Hub-модель под их продуктовый кейс и бюджет. Ассистент должен работать через Google ADK (Python) и быть доступен по OpenAI-совместимому API.

## 2. Задача

Реализовать сервис-ассистент, который:

- Принимает от пользователя описание кейса (тип нагрузки, формат запросов, примерный объем трафика, требования к качеству) и бюджет.
- Анализирует документацию по моделям GPT Model Hub в MWS:
  - https://mws.ru/docs/cloud-platform/gpt/general/gpt-models.html
- Выбирает одну или несколько подходящих моделей и объясняет выбор.
- Строит понятный краткий отчет с расчетами стоимости (оценка стоимости на заданный объем использования, указание тарифов, какие лимиты/ограничения релевантны).
- Поддерживает диалог: пользователь может уточнять вводные и задавать дополнительные вопросы в рамках одной сессии.

## 3. Требования

### Функциональные

1. Реализовать OpenAI-совместимый API к ассистенту:
   - минимум один эндпоинт (на выбор);
   - формат запроса и ответа должен соответствовать спецификации выбранного эндпоинта.
2. Использовать Google ADK (Python) как основу для ассистента/агента. Реализовать агентский архитектурный паттерн (на выбор), при этом в README обязательно описать выбранный паттерн.
3. Ассистент должен уметь:
   - получать данные о моделях и их стоимости с сайта MWS в рамках сессии;
   - рассчитать примерную стоимость использования для заданного сценария;
   - выдать текстовый отчет в ответе API в структурированном виде:
     - блок «Входные данные»;
     - блок «Рекомендованные модели»;
     - блок «Расчеты»;
     - блок «Пояснения/ограничения».

### Нефункциональные

1. Код должен быть оформлен в виде репозитория (GitHub/GitLab/Bitbucket) с README.
2. README должен содержать:
   - краткое описание задачи;
   - архитектурную схему/описание (как минимум текстовое), роли агентов;
   - пример запроса и ответа к API;
   - инструкции по локальному запуску (команды, env-переменные).
3. Решение должно быть воспроизводимым локально: достаточно `docker-compose` или простой инструкции по запуску (`venv` + команда).

## 4. Ограничения

1. Данные о стоимости моделей GPT Model Hub должны динамически забираться с сайта MWS в рамках сессии (через HTTP-запросы, парсинг и т.п.).
   - Нельзя хардкодить прайсы в коде.
   - Нельзя «узнать прайсы» через LLM (prompt-engineering).
   - Разрешено использовать in-memory кеш в пределах одной сессии/запуска сервиса.
2. Допускается использовать любые дополнительные библиотеки (`requests`, `pydantic` и т.д.), кроме полноценных web-фреймворков.
3. Язык реализации — Python 3.10+.

## 5. Бонусные требования

Следующие пункты не обязательны, но будут плюсом:

1. Реализация stream-ответов OpenAI API (`stream=True`) от ассистента.
2. Автотесты (минимум для расчета стоимости и выбора модели).
3. Минимальная observability: логирование ключевых шагов и/или простая метрика (кол-во запросов к сайту с тарифами, время ответа).
4. Валидация входных данных (`pydantic`/другая библиотека).

## 6. Формат результата

Кандидат должен предоставить:

1. Ссылку на репозиторий с кодом.
2. README, соответствующий требованиям выше.
3. Краткое описание принятых архитектурных решений (можно отдельным разделом в README).
4. Один или несколько примерных сценариев использования (sample requests + ожидаемые ответы).
